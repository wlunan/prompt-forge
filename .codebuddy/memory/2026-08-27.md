# 2026-08-27

## 备份功能升级：完整数据包
- 需求：将「导入/导出」从仅提示词裸数组升级为完整可恢复数据包
- 用户决策：
  - 导入策略：合并（去重追加，非覆盖）
  - 种子数据：排除（备份不导出内置 seed 提示词）
  - 项目冲突：相同 ID 跳过（防重复导入）
  - settings：逐字段合并
  - 历史记录：**保留导出**（统计面板依赖 historyItems）

### 数据全景（4 份 KV 文档，key 前缀 promptforge:）
- `prompts` → PromptItem[]（核心，含 projectId/variables/snapshots/deleted）
- `projects` → Project[]（组织结构，被 prompts 引用）
- `settings` → Record（行为设置 closeAfterCopy/autoFocus/maxHistory + 主题 theme，合并存同一 key）
- `history` → HistoryEntry[]（运行时数据，统计面板依赖）

### 实现
- 新增 `src/utils/backup.ts`：
  - `SEED_PROMPT_IDS` 常量：['welcome','tutorial-vars','frag-style','frag-markdown']（seed 数据用固定字符串 ID，非 UUID，可识别）
  - `buildBackup()`：组装数据包 `{ format:'promptforge-backup', version:1, exportedAt, prompts, projects, settings, history }`，排除 seed
  - `parseBackup()`：解析，兼容旧版裸数组（Array → 只含 prompts）
  - `mergeBackup()`：合并逻辑——项目按 ID 去重、提示词按 ID 去重 + projectId 悬空校验（指向不存在项目则清空转资产）、settings 逐字段合并、history 按 ID 去重
- 改造 `SettingsView.vue`：
  - exportJson → buildBackup（含 projects/settings/history）
  - importJson → parseBackup + mergeBackup，写回 promptStore.rawItems / projectStore.items / historyItems，并 persistAll + saveProjects + saveHistory + setSettings
  - `applyImportedSettings()`：settings 写回行为字段（appSettings）+ 主题（theme.set），一次性 setSettings 写完整（避免 app.save 覆盖 theme 的 bug）

### 发现隐患（未修复）
- settings 双写 bug：`app.save()` 用 `{...settings.value}` 覆盖，`theme.persist()` 用 `{...existing, theme}` 合并，两者顺序不当会互相覆盖。本次导入用一次性 `setSettings` 规避，但 app store 的 save 逻辑本身仍是隐患，后续可统一为合并写入
- 项目 ID 冲突场景：跨设备同名不同 ID 项目会并存（按 ID 去重，不按 name 合并）
